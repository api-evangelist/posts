      <div class="mb-2" style="max-width: 46rem;">
        <p class="mb-3">Most organizations cannot tell me how many APIs they operate, and the surveys back that up &mdash; a majority of technology leaders do not know the real number, and on average there are meaningfully more APIs running in production than anyone is aware of. That gap is where the risk lives. The APIs you have cataloged are not the ones that hurt you; the undocumented, unowned, and forgotten ones are.</p>
        <p class="mb-3">I help you find them. Discovery is not a single scan you run once &mdash; it is a combination of methods stitched together: analyzing real traffic to see what is actually being called, scanning code repositories for endpoints, reviewing whatever documentation already exists, and probing for the shadow, rogue, and zombie APIs that never made it onto anyone's list. The goal is an honest, complete picture of your API landscape as it really is, not as an old spreadsheet says it should be.</p>
        <p class="mb-3">This is the unglamorous first step that makes everything else possible. You cannot secure, govern, retire, or bill for an API you do not know exists. Before we talk about gateways, policies, or lifecycle, we complete the map &mdash; and almost every map I complete turns out to have been missing pieces the organization was certain it had covered.</p>

        <h2 class="fs-6 fw-semibold mt-4 mb-2">What you walk away with</h2>
        <ul class="text-muted">
          <li>A discovered list of the APIs and endpoints you actually run, including the ones nobody knew about</li>
          <li>Shadow, rogue, and zombie APIs surfaced and flagged for triage</li>
          <li>A repeatable discovery approach wired into traffic and repository scans, not a one-time audit</li>
        </ul>
