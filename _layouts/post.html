{{ content }} {%- comment -%} Mid-article paper slot. The ad network already runs on every post (top-banner and content-bottom in the default layout), and it already rotates, counts impressions and clicks per slot in DynamoDB, and emits the correct ae_* attribution. What it did not have was a placement inside the article, which is where a reader who is actually engaged sits. It has to be injected client-side: {{ content }} is a single Liquid value with no midpoint to address, and GitHub Pages ignores custom _plugins so a content filter is not available either. embed.js already runs a MutationObserver over the document, so a div added after load is picked up with no change to the ad server. Only on posts long enough to have a real middle. On anything shorter the "midpoint" is a couple of sentences from the top and the slot just reads as a second banner. {%- endcomment -%}
