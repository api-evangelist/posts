Today in my run through companies that publish an A2A agent card I am looking at Qonto, the European business banking platform, and setting it next to Revolut Business and N26. For context, I wrote about the [934 conformant A2A agent cards and who is publishing them](https://apievangelist.com/2026/11/10/934-conformant-a2a-agent-cards-and-who-is-publishing-them/), and you can browse every card in the [APIs.io A2A catalog](https://apis.io/a2a/), which as of November 10, 2026 lists 1,279 providers serving a card and 934 conformant.

## What Qonto Publishes

Qonto's card lives at `https://docs.qonto.com/.well-known/agent-card.json`. You can see it on the [Qonto agent card page](https://apis.io/a2a/qonto/) and the [Qonto provider page](https://apis.io/providers/qonto/) on APIs.io. It is a docs-platform card. The name is "Qonto," the protocol version is 0.3, the preferred transport is HTTP+JSON, and the endpoint is the docs site, `https://docs.qonto.com/`.

There is one skill, with the id `qonto`. Its description starts "Use when building integrations with Qonto's banking, payments," and that is the shape I see on a lot of cards generated by documentation platforms. It is telling an agent that there are docs here for building integrations. It is not describing a task an agent can hand off.

When I checked on November 10, 2026, the live card matched what APIs.io recorded on October 12. APIs.io grades it conformant with one deviation noted, `supportedInterfaces` used in place of `additionalInterfaces`. My own probe treats that field more strictly and estimated near-conformant. Same finding, weighed differently. The main `qonto.com` domain returned 403 at both well-known paths, which most likely means a bot shield, so I can't say what is or is not there.

Qonto also serves `https://docs.qonto.com/llms.txt`, which opens by saying Qonto provides two collections of REST APIs and a Sandbox environment.

## Revolut Business

I checked `revolut.com` and `developer.revolut.com` at both `/.well-known/agent-card.json` and `/.well-known/agent.json`. `revolut.com` returned 404 at both. `developer.revolut.com` returned 200 at both, but with an HTML page, not JSON, which is a soft 404 and not a card. I found no agent card. I also tried `developer.revolut.com/llms.txt` and got a 403, so I can't tell you whether one exists. Revolut has a [provider page on APIs.io](https://apis.io/providers/revolut/) but no A2A card page.

## N26

I checked `n26.com` and `docs.n26.com` at both well-known paths. `n26.com` returned 404 at both and `docs.n26.com` returned 403 at both. I found no agent card. N26 is on APIs.io as a [provider](https://apis.io/providers/n26/), without an A2A card.

## What This Tells Me

Qonto is ahead of these two on discovery, and I want to be clear about what that means. An agent or a registry that crawls well-known paths will find Qonto, learn there is developer documentation, and learn it covers banking and payments integrations. That is useful. It is how Qonto ended up in the APIs.io catalog with a card at all.

But it is a docs card. The endpoint is a website. There is one skill and it describes documentation, not an action. An agent can't send Qonto a message that says "pull last month's transactions" or "draft a transfer" through this card. The card is a pointer to the docs that explain how a human developer would build that.

For a bank that is a reasonable place to be. Money movement through an autonomous agent raises real questions about consent, strong customer authentication and liability, and I would rather see a bank publish an honest docs card than a rushed agent endpoint. The 403 responses on `qonto.com` and `docs.n26.com` are a reminder of the other side of this: banks protect their domains hard, and that also blocks the crawlers that would discover a card.

## Takeaway For Business Banking APIs

If you run a business banking API in Europe, the cheapest move is the one Qonto already made: let your docs platform publish a card, then edit the single skill so it names the actual APIs, accounts, transactions, transfers, cards, and the sandbox, instead of a generic sentence. Fix the `supportedInterfaces` field while you are in there. If your security layer blocks `/.well-known/` paths, make an exception for the agent card and llms.txt so they can be found. The step after that, an agent endpoint with read-only skills first, is where the real differentiation will be.
