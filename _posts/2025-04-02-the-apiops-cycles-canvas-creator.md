I was talking with Marjukka and Claire as part of regular discussions around governing API operations, and Marjukka shared their [APIOps Cycles Canvas Creator](https://canvascreator.apiopscycles.com/)--I have had it open and playing with it every since. The simple interface allows you to define API operations using the following ten APIOps Cycles Canvases.

- [**API  Value Proposition Canvas**](https://www.apiopscycles.com/resources/api-value-proposition-canvas) - The API Value Proposition Canvas defines how an API delivers value by linking user tasks and challenges to API features.
- [**Customer Journey Canvas**](https://www.apiopscycles.com/resources/customer-journey-canvas) - Visualize, iterate, and optimize the target state customer journey while identifying gains and pains.
- [**API Business Model Canvas**](https://www.apiopscycles.com/resources/api-business-model-canvas) - How feasible and reusable will this API be? Use API Business Model canvas to evaluate the business case from a cost-benefit perspective.
- [**Business Impact Canvas**](https://www.apiopscycles.com/resources/business-impact-canvas) - The Business Impact Canvas helps to identify and mitigate risks related to API availability, security, and functionality to support informed architectural decisions.
- [**Locations Canvas**](https://www.apiopscycles.com/resources/locations-canvas) - Map the regulatory, compliance, and network locations of API providers and consumers to ensure accessibility and compliance.
- [**Capacity Canvas**](https://www.apiopscycles.com/resources/capacity-canvas) - The Capacity Canvas aligns business transaction patterns, future consumption trends, and technical solutions to ensure API scalability and performance.It provides critical input for scaling decisions and infrastructure planning.
- [**Domain Canvas**](https://www.apiopscycles.com/resources/domain-canvas) - Define core entities, their attributes, and relationships to create a shared conceptual understanding across APIs.
- [**REST API Design Guide**](https://www.apiopscycles.com/resources/rest-api-design-guide) - How should endpoints, i.e. the resources that our API allows the API consumers to use, be named? What features and thus endpoints should be included in the same API? To version or not and how?
- [**API Audit Checklist**](https://www.apiopscycles.com/resources/api-audit-checklist-main) - Use this checklist to audit your API prototype or a ready made API before publishing it to stakeholders, or, why not before buying an API
- [**Interaction Canvas**](https://www.apiopscycles.com/resources/interaction-canvas) - Plan and design API interactions, focusing on workflows, inputs, outputs, and potential exceptions.

The APIOps Cycles Canvas Creator lets you choose English or Journey and from each of the ten APIOps Canvases. Once you have fleshed out the areas of the canvases that matter to your API you can export JSON or as SVG, and of course you can also then import the JSON, starting from where you left off or collaborate and share with others.
