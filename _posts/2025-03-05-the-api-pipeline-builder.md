To help me better see the pipeline layer we use to deliver our APIs I retrofitted the [API Evangelist API Platform Builder](https://engineering-platform-builder.apievangelist.com/) to only have specs and open-source tooling, and organized using some semantic areas of what I see companies trying to accomplish via their API pipelines. Like the other builder, the API Evangelist API Pipeline Builder is meant to be interactive and I can add and remove any specs and tools to it, and eventually I’ll add in more commercial services.

<center><a href="https://pipeline-builder.apievangelist.com/"><img src="https://kinlane-productions2.s3.us-east-1.amazonaws.com/pipeline-builder-screenshot.jpg" style="width: 95%: margin: 15px;"></a></center>

These builders help me see API operations. This helps me write more stories that define each layer. I want to explore a design-first as well as a code-first iteration of this pipeline builder. I want to also think about what needs to be in the pipeline for schema registries and moving specifications and standards forward. Next, I will go through each of the tools I have listed and add drag and droppable icons for each capability, helping me be even more precise.
