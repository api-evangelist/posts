Most of the agent cards I have been looking at in this series are generated by documentation platforms. Today's is not. 1inch publishes a card for something it calls the "1inch Business Agent," with its own endpoint and nine skills. I am setting it next to Uniswap and 0x. Background is in my post on the [934 conformant A2A agent cards and who is publishing them](https://apievangelist.com/2026/11/10/934-conformant-a2a-agent-cards-and-who-is-publishing-them/), and every card is in the [APIs.io A2A catalog](https://apis.io/a2a/), which as of November 10, 2026 lists 1,279 providers serving a card and 934 conformant.

## What 1inch Publishes

The card is at `https://business.1inch.com/.well-known/agent-card.json`. APIs.io has it on the [1inch agent card page](https://apis.io/a2a/1inch/) and the [1inch provider page](https://apis.io/providers/1inch/). It declares protocol version 0.3.0, JSON-RPC as the preferred transport, and an endpoint at `https://api.1inch.com/mcp/protocol`. The description is upfront that the agent is "Implemented as a remote MCP server." That is honest, and it is a pattern I am seeing more: one service, described both as an MCP server and as an A2A agent.

The nine skills, when I checked on November 10, 2026:

- **search**: search the 1inch Business documentation and API reference.
- **list_examples** and **get_example**: list and fetch SDK code examples.
- **aqua**: read Aqua analytics and preview, create or close maker positions, with the wallet doing the signing.
- **swap**: quote and execute swaps, covering Pro, Gasless Swap and Gasless Cross-chain Swap.
- **orderbook**: build, create, list and cancel limit orders. Requires authentication.
- **product_api**: an authenticated proxy to portfolio, spot prices, token metadata and gas prices.
- **walletconnect**: a non-custodial WalletConnect flow to pair a wallet, sign and send transactions.
- **debug**: look up recent API request logs. Authenticated and read-only.

The live card has changed since APIs.io fetched it on July 28. The `aqua` skill was "Aqua strategy analytics" and read-only. It is now "Aqua positions" and includes creating and closing positions. The swap skill used to say Classic and Fusion and now says Pro and Gasless. The skill count is still nine, and my probe still estimates it as conformant with no issues.

What I like here is that each skill says whether it is public, read-only or requires authentication, and that the write paths are non-custodial. That is exactly the information an agent needs before it decides whether to call something.

## Uniswap

I checked `uniswap.org`, `docs.uniswap.org` and `app.uniswap.org` at both `/.well-known/agent-card.json` and `/.well-known/agent.json`. The first two returned 404. `app.uniswap.org` returned 200 with HTML, which is the app shell, not a card. I found no agent card. Uniswap does serve `https://docs.uniswap.org/llms.txt`, which covers the Uniswap API, SDKs, v4, v3 and v2 contracts, UniswapX, Permit2, Universal Router and Unichain.

## 0x

I checked `0x.org`, `docs.0x.org` and `api.0x.org` at both well-known paths and got 404 on all six. I found no agent card. 0x serves `https://docs.0x.org/llms.txt`, and it includes a section titled "Instructions for AI Agents," which is a nice touch. So 0x is writing for agents, just through llms.txt rather than A2A.

## What This Tells Me

1inch is doing something different from almost every docs-platform card I have covered. The endpoint is an API host, not a website. The skills are verbs a developer or an agent would actually use: swap, place a limit order, check a portfolio, debug a request. Some are public and some need a key, and the card says which.

Uniswap and 0x both clearly care about agent consumers. Their llms.txt files are substantive. But llms.txt helps a model read your docs. An agent card with skills and an endpoint tells a client what it can ask you to do. Those are different jobs.

The one caution I'd add is protocol version. 1inch is on 0.3.0. As A2A moves toward 1.0, keeping the card current is ongoing work, and the drift I saw between July and November shows 1inch is already maintaining it.

## Takeaway For DEX And Aggregator APIs

If you run a swap API, look at what 1inch put on this card: public versus authenticated, read versus write, and non-custodial signing, stated per skill. You already have the operations. Publishing a card on your API or business domain, pointing at a real endpoint, is a small step past the llms.txt you have already written, and right now it is what puts you in front of agents that discover through registries.
